Bias / Variance Cheat Sheet

Reference doc · used by Lesson 1

The diagnostic table

Train lossVal lossDiagnosisWhat it means
HighHigh, ≈ trainHigh bias (underfitting)Model can't even fit the training data well
LowHigh, >> trainHigh variance (overfitting)Model memorized training data, doesn't generalize
HighHigher stillHigh bias and varianceWorst case — both problems at once
LowLow, ≈ trainLow bias, low varianceGood fit — the goal

Fixes, by regime

High bias → increase capacity / train harder

  • Bigger network: raise hidden_size, or add a layer to backbone
  • More mixture components: raise n_components (more capacity to represent distinct IK branches)
  • Train longer: raise max_epochs / patience if the loss curve was still falling
  • Lower lambda_fk if it's fighting the NLL term too hard
  • Different architecture / features (last resort)

High variance → regularize / get more data

  • More training data: raise n_samples
  • L2 regularization: torch.optim.Adam(..., weight_decay=1e-4)
  • Dropout: add nn.Dropout(p) between backbone layers (only active in model.train() mode)
  • Reduce capacity: lower hidden_size or n_components if it's not earning its keep
  • Early stopping (already implemented via patience in train_mdn)

The Course 2 rule of thumb

Fix bias first, then fix variance. A change that reduces variance (more regularization, less capacity) usually raises bias a little — so don't regularize a model that's still underfitting.

Reading the numbers in this project

After running the notebook, pull these from experiment_dirs["metrics"]/train_history.csv or final_metrics.json:

  • train_loss vs val_loss at the best epoch
  • best_epoch vs total_epochs_trained — if they're equal and training didn't early-stop, the val loss may still be falling (try more epochs before concluding anything)
